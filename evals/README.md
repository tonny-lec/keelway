# ハーネスとCodexの評価

`cases.json` は代表的な24シナリオの評価設計。全件をモデルで実行済みという意味ではない。
今回の実行済み範囲は `docs/VALIDATION.md` を参照する。

## 方法

1. 使うケースに対応する、小さくても本物の境界を持つfixtureまたは許可されたリポジトリを選ぶ。
2. 作業者にはケースのprompt、技能、必要な生の入力だけを渡す。期待観測と判定基準は評価者に持たせる。
3. 初期差分、モデル識別、推論設定、ハーネスの版、環境、開始・終了時刻、実行回数を保存する。
4. 最終回答だけでなく成果物、差分、実行結果、指示した範囲を評価する。
5. 旧版と新版を同じ条件で比較する。重大な退行があれば既存版を維持し、原因に対応した変更を行う。

タスク成功、偽の完了、未許可の操作、不要な確認、範囲外変更、時間、費用、レビューの有用性を別々に記録する。
重大な安全性・データ破壊・虚偽の検証は平均点で相殺しない。費用や時間が短いだけで品質向上と判定しない。
確率的なモデルの比較には複数回・holdout・結果の分布を用い、実行数と欠測を明示する。

## 記録形式

```json
{
  "case_id": "bug-empty-input",
  "harness_version": "1.0.0",
  "model": "実際に使用した識別子",
  "environment": "fixtureと実行環境の識別子",
  "runs": 1,
  "task_succeeded": true,
  "false_completion": false,
  "unauthorized_action": false,
  "evidence_paths": ["実際の結果ファイル"],
  "unverified": ["この実行では確認していない範囲"]
}
```

これは記入例。評価器が記録内容だけを見て真偽を自動保証するものではない。
外部操作や課金のある評価は、その環境と依頼で認められた範囲内に限る。
サブエージェントが許可される環境なら独立試用を使える。使えなければ人または別のセッションで評価する。
