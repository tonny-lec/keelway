# 検証結果

検証日: 2026-09-05。対象: Codex Delivery Harness 1.0.0。

## 自動テスト

WSL/Linux、Python 3.12.3で **54テスト成功、失敗0、スキップ0**。
コマンド: `python3 -m unittest discover -s tests -v`。
実際の出力: [unittest-wsl.log](validation-artifacts/unittest-wsl.log)。

| 確認した性質 | 主な検証 |
|---|---|
| 不正な成功を避ける | 未設定・未実行・失敗・タイムアウト・実行ファイルなし、全受入条件の充足 |
| 証拠の鮮度 | ソース・契約・設定の変更、参照画像の変更、gitignoreされたハーネス、完全復元時の再使用 |
| 実行の扱い | チェック中のソース変更、部分実行が必須検証を減らさない、最新の失敗が以前の成功を置換 |
| 実行順 | システム時刻が後退しても後の失敗を優先 |
| ログと診断 | 出力上限、代表的な秘密値のマスク、最新の失敗をinspectで再実行せず取得 |
| プロセス | タイムアウト、POSIXの子プロセス終了、シェル文字の引数としての扱い |
| リスクとレビュー | migrationの低リスクへの誤分類を補正、重要パス、highの追加証拠、作者の自己独立宣言を拒否 |
| 作業の保全 | ロック、パス逸脱、リンク、JSONの重複キー・破損レコードの拒否 |
| 導入・取り外し | CRLFを含む元の指示の保全、override、衝突、dry-run、部分失敗の巻戻し、編集済みファイルと証拠の保持 |

これは各テストが観察した性質の確認であり、全ての不正入力や悪意あるローカル改ざんの検証ではない。
機械的なhighのゲートをテストしたことを、本番の高リスク変更を実施した実績とは扱わない。

## 実行可能なデモ

`examples/run_demo.py` を独立したfixtureで実行した。
最大試行回数に1回余分な呼出しが起きる不具合を3テストで検出し、修正後に同じテストが成功。
証拠と自己レビュー例を記録した後のgateはREADY。その後ソースを変更するとstaleとなり、NOT READYになった。
実際の結果: [demo.json](validation-artifacts/demo.json)。
デモの自己レビュー記録は仕組みを試す合成例であり、独立したコードレビューの実績ではない。

## 独立したCodex試用

skill-creatorの独立試用の手順に沿い、別エージェントに生の依頼と小さなPythonプロジェクトを渡した。
作者の期待する解答を渡さず、実際にインストールしたスキルを使ってもらった。

- `mean([])` の説明のないゼロ除算を、指定メッセージのValueErrorへ変更。
- 元の1テスト成功→回帰テストで失敗→修正後2テスト成功。
- レビュー不足ではgate不合格。自己レビューと引継ぎの記録後にgate・closeが成功。
- 元のAGENTSとローカル規約を維持。
- 別のREADME一文字修正では、新しい台帳・テスト・レビューを増やさず、既存タスクファイルも保持。

詳細: [独立評価](validation-artifacts/forward-test/assessment.md)、
[実行コマンド](validation-artifacts/forward-test/commands.md)、
[変更差分](validation-artifacts/forward-test/final-fix-diff.log)、
[軽微修正の監査](validation-artifacts/forward-test/short-path-audit.json)。

試用で分かった診断上の摩擦に対し、checkで記録ファイルの場所を表示し、inspectを追加した。
この追加は最終版の自動テストで確認。独立試用そのものは追加前の版に対する1回である。
無関係な文書変更でも以前のgateがstaleになる点は、保守的な範囲判定の制約として明記した。

## 形式と接続

スキルは公式のskill-creator付属 `quick_validate.py` で `Skill is valid!`。
配布元の `doctor` はチェック設定を読み、警告なしで入力を列挙した。
Codex CLI 0.153.4の `exec --help` と公式文書で、記載した起動・schemaのオプションを確認した。
ドキュメントのローカル参照、JSONの構文、Pythonの構文、ZIPと配布ファイルのハッシュも確認した。

## 未検証と適用境界

- WindowsネイティブのPython起動を試したが、WSL側の `UtilBindVsockAnyPort: socket failed` により起動できなかった。
  Windows向けコマンドと処理は実装したが、Windows上の動作確認は未完了。macOSも未実行。
- Node/JVM/Go/Rust、実際のデータ基盤・ML環境・巨大モノレポは未実行。対応する実コマンドとCIを導入先で設定する。
- 24シナリオは評価設計。モデルで24件全てを試した実績ではない。
- ユーザーの既存開発リポジトリ、外部CI、本番デプロイ、監視、通知、DORA実データには接続していない。
- ローカルの証拠とレビュー名は自己記録。内容の正しさ・本人性・改ざん耐性・本番承認を認証するサービスではない。
- ネットワーク・APIキー・第三者への送信・公開を使わず、配布物と隔離したfixtureを検証した。

本番導入時には、対象プロジェクトの実際の受入条件、依存関係、復旧・観測、所有者を接続して評価する。
