# 必要な部分だけ使う成果物の型

既存の文書・チケットへ追記できるなら新規ファイルを作らない。記入欄は確認できた内容で置き換える。
記入しただけでは証拠にならない。コマンド結果、コード、実測、出典、観察を結び付ける。

## 依頼の契約

```text
利用者と期待する変化:
対象 / 非対象:
受入条件（外から観測できるもの）:
根拠となる現状・出典:
リスクと理由:
重要な不変条件・互換性:
確認が必要な未知 / 採用した仮定:
変更・レビュー・提供の所有者:
```

## 意思決定（必要な場合）

```text
問題と制約:
比較した選択肢:
決定と理由:
費用・複雑さ・運用への影響:
確かめる方法と結果:
撤回・再検討の条件:
```

## 変更の説明・PR

```text
問題と変更後の挙動:
影響する利用者・呼出し側:
受入条件と検証結果（実行・手動・未実行を区別）:
互換性と提供時の扱い:
残る制限:
```

## レビューの証拠

```text
対象の版・差分:
担当と評価方法（作者による見直し / 実際に別の主体が評価）:
確認した契約・重要経路:
確認した失敗・境界ケース:
指摘（発生条件・場所・影響・根拠）と解消確認:
確認できなかった範囲:
結論と理由:
```

## 提供・移行・復旧

```text
対象環境・利用者範囲・成果物の版:
実施主体と現在の許可の根拠:
新旧の互換性と混在期間:
段階ごとの対象・開始条件:
観測する指標・比較基線・母集団・期間:
データ欠落時の扱い・中止条件:
復旧する操作・対象版・必要権限:
データと外部副作用の戻せる範囲 / 戻せない範囲:
リハーサルと照合の証拠:
バックフィルの冪等性・中断再開・負荷制御:
旧構造・フラグの撤去条件、担当、期限:
実施結果と提供後の効果確認:
```

## 障害と学習

```text
利用者影響・対象範囲・開始時刻:
観測した時系列（時刻 / 事実 / 操作 / 結果）:
検知・緩和・復旧の証拠:
寄与した技術・組織上の条件:
機能した防御 / 改善する防御:
再発や影響を減らす対応（担当 / 完了条件 / 優先度 / 見直し日）:
実際に改善したか確認する指標:
```

## 再開用メモ

```text
依頼と現在の契約:
完了した成果と証拠の場所:
最後に確認した差分・環境:
残る作業・不明点・依存:
既に得ている許可と範囲:
次の具体的な一手:
```
