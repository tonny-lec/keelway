# プロジェクトの作業地図

初回の仕事で、確認できた事実だけを必要な節に追記する。全節を埋めることは開始条件ではない。
各項目に情報源のファイルまたはURL、確認日、更新担当を添える。秘密値は書かない。

## 利用者と価値

利用者、困っていること、成功の観測方法、今回の非対象。

## 実行方法

起動、依存関係の再現、既存CI、テスト、型・静的検査、ビルド。実行可能な配列を project.json に登録する。

## 境界と不変条件

サービス・モジュール・データの責務、重要な呼出経路、依存先、権限・公開契約、破ってはいけない振舞い。

## 所有と提供

担当チーム、レビューの窓口、提供経路、復旧方法、運用連絡先、既存の承認方針へのリンク。

## 観測と学習

利用者の成功指標、SLO、実測のベースライン、既知の制約、最近の意思決定・障害学習へのリンク。
